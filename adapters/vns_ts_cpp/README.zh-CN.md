# VNS/TS（C++ 复现）

按 Schneider, Stenger, Goeke (2014), *The Electric Vehicle-Routing Problem with Time Windows and Recharging Stations*, Transportation Science 48(4) 复现的单线程 C++17 实现。输入为电动适配器 `_native_input` 写出的显式矩阵文件，输出为每个改进可行解一行的 JSON 事件流，字段与 HMA 的事件流相同（`routes`、`internal_objective`、`stage`、`elapsed_s`）。

```bash
g++ -std=c++17 -O2 -o vns_ts vns_ts.cpp
./vns_ts INPUT --events events.jsonl --seed 20261103 --budget 60
./vns_ts INPUT --events events.jsonl --seed 20261103 --deadline-monotonic <CLOCK_MONOTONIC 秒>
./vns_ts INPUT --probe <站点编号>     # 输出：弧耗电 kWh、充电秒数、离站可用电量 kWh
```

## 因题设不同而调整的部分

1. **目标**：论文先最小化车数再最小化距离。本基准只最小化总距离、车数不限。因此移动的比较只用广义代价，不再有“减少车数优先”的规则。
2. **车数管理**：论文给定车数，可行性阶段经 η_feas 次迭代仍不可行才加一辆车。这里始终保留一条空路线，搜索可随时开新路线，取代显式的 addVehicle。可行性阶段不再因车数不足而反复等待。
3. **初始解的开线条件**：论文在容量或电量违反时开新路线，时间窗不保证。这里默认在出现时间惩罚时也开新路线（`--init-time-check 1`），使大规模实例能很快得到可行解。设为 0 即为论文原规则。
4. **终止**：论文按迭代数终止。基准按墙钟时限运行，一次完整运行（可行性阶段加 η_dist 次迭代）结束后以新的随机初始解重启，保留全局最好可行解，直到截止时间。
5. **惩罚的量纲**：论文的需求、时间、电量与距离同量级。这里容量以 cm³、时间以秒、电量以 kWh 计，因此先换算为距离当量再乘论文的权重：时间按平均速度、电量按平均能耗换算，容量超出一个整车容量计为 0.2 倍参考距离。
6. **非对称矩阵**：全部距离、时间、能耗均按有向弧取值。2-opt* 不反转路线方向，其余算子也不依赖对称性。

## 简化的部分

- **禁忌属性**：论文为 (弧, 路线, 前后站点)。这里为 (弧, 路线)，不区分路线内的站点区间。
- **多样化属性**：论文为 (顶点, 路线, 前后站点)，这里为 (顶点, 路线)，并按已执行的移动数归一化频次。
- **移动评估**：每个候选移动重新计算受影响路线，复杂度与路线长度成正比，而非论文的常数时间。
- **生成弧列表**：默认使用预处理后保留的全部弧。`--granular K` 只保留每个顶点最近的 K 个顶点，仓库和站点始终保留。论文未给出稀疏化阈值。

## 已做的验证

在合成实例上运行，并用独立编写的检查器逐个核对所有输出的解：客户恰好一次、容量、硬时间窗与等待、每弧到达电量、进站充满的时长、回仓时刻、总距离。

| 实例 | 时限 | 首个可行解 | 结果 |
|---|---|---|---|
| 30 客户、5 站 | 20 s | 0.00 s | 33 个解全部通过 |
| 100 客户、10 站，电量和时间窗起作用 | 20 s | 0.01 s | 149 个解全部通过，最终 7 条路线、5 次充电 |
| 100 客户、10 站，约束宽松 | 20 s | 0.01 s | 47 个解全部通过 |
| 500 客户、30 站，全部弧 | 30 s | 0.19 s | 97 个解通过，165 次禁忌迭代 |
| 500 客户、30 站，`--granular 30` | 30 s | 0.23 s | 399 个解通过，1,810 次禁忌迭代，距离更短 |

**尚未做的验证**：没有在 Schneider 的原始基准实例上与论文公布结果对比，也没有在 EVRPTW-D 的真实实例上运行。
